# Optional remote model adapters

**Status (2026-11-04):** adapter configuration and mocked HTTP-contract tests are implemented. No provider credential is configured and no live provider call has been made. Meta's current first-party docs now confirm this code's `https://api.meta.ai/v1/chat/completions` endpoint and `muse-spark-1.3` model. This does not establish that the account has access/credits or that the entrant/project is eligible.

## Runtime and privacy contract

- Remote mode is off by default. The UI requests `/api/health` before asking for consent; it will not turn remote mode on unless the server reports a supported, configured provider. The confirmation names that provider. If unavailable, authored dialogue remains available and no question is sent.
- `MODEL_PROVIDER` is server-only configuration (`meta`, `baseten`, `fireworks`, or `modal`). A browser request cannot choose a provider, model, URL, or key.
- The same-origin conversation request includes explicit consent, world `self`, the typed question (350 characters maximum), an allowlisted fictional timeline summary, and an opaque configuration fingerprint. The server rejects a fingerprint that no longer matches the configured provider, endpoint, and model before any inference. It never includes a passphrase, save, private letter, NPC memories, or other branches.
- Baseten, Fireworks, and Modal use a non-streaming chat-completions body with `model`, `messages`, `max_tokens`, and `stream:false`. The existing Meta adapter retains its prior body shape. The response must contain text at `choices[0].message.content`; ELSEWHERE parses and validates that text locally. No `response_format`/JSON-mode flag is sent. Invalid output, provider errors, timeout, or cancellation cannot change authoritative game state; the client uses authored fallback.
- Partner calls use a 30-second overall deadline; Meta retains its existing 12-second deadline. The browser deadline adds five seconds of response grace so it does not cancel a valid partner response at 11 seconds. Both local and serverless bridges keep the deadline active through body parsing, reject redirects, and abort upstream work when the browser disconnects. No automatic retry is performed: transient 429/5xx conditions use the safe local fallback and the player can deliberately retry, avoiding hidden duplicate inference/billing. Cancellation is best effort and is not a billing guarantee.
- Health responses expose a provider ID, configuration booleans, bounded timeout, and an opaque fingerprint of the provider/endpoint/model; they do not reveal a model ID or credential. Provider credentials remain in server environment variables and are never returned to the browser or included in logs.

`.env.example` contains empty placeholders only. Remote calls require the exact operator setting `REMOTE_MODEL_ENABLED=true` as well as provider credentials; missing, malformed, or any other value leaves the serverless and local bridges offline. Keep it `false` for authored play. Do not create/configure credentials, publish an endpoint, or make a live call without the owner's specific authorization. `npm run dev:model` starts the same-origin local bridge plus Vite; `npm run dev` remains offline and does not start it. The legacy `npm run dev:meta` command remains available for compatibility. The flag is an operator opt-in, not abuse protection or a spend cap; public hosting still needs provider-side budget and rate controls.

The Node bridge accepts conversation POSTs only through the local Vite browser flow: an exact HTTP `localhost` or `127.0.0.1` Origin on ports 5173–5189 and `application/json` (case-insensitive, optional parameters). Missing or other Origins return 403; unsupported content types return 415 before body reads, rate-limit use, or inference. The browser Origin is checked independently of Host, which Vite can rewrite when proxying. Custom ports outside this range and direct POSTs without Origin are intentionally rejected. Health GETs remain available; preflights receive no CORS permission. These browser-origin checks are not authentication for a public API: keep the bridge local and remote inference off until separately authorized and protected.

## Contract verification

`tests/provider-config.test.mjs`, `tests/provider-contract.test.mjs`, `tests/local-provider-contract.test.mjs`, and `tests/meta-request.test.mjs` use synthetic credentials and mocked responses only. They verify fixed/validated endpoints, server-only selection, provider-specific model requirements, non-streaming partner request bodies, Bearer headers, response validation, safe failure, timeout and client-disconnect cancellation. Browser lifecycle coverage verifies unavailable-provider refusal, dismissed and accepted consent, the displayed Baseten recipient, and mocked dialogue. These tests are not live provider evidence.

Modal and Fireworks account/model availability must be checked by an authorized operator before configuration. Baseten partner access and the named model ID do not prove competition eligibility or authorize spend. The live Meta/API and public-release gates in [hackathon readiness](HACKATHON_READINESS_CURRENT.md) remain unchanged.

## Prepared single-request verification

`npm run meta:probe` is safe without `--live`: it reports NOT RUN and makes no request or receipt. After separate credential and cost authorization, the operator can run `npm run meta:probe -- --live` with the approved server environment already supplied. It uses the same selected provider and consent-version contract as the serverless handler; it sends only one fixed fictional question/summary and never reads a vault or chat history. No credential setup or live request was performed during this implementation.

The ignored `review-output/meta-live-check.json` receipt records provider/configured model, timestamp, handler status, upstream status if received, attempt count, dialogue validity, directed cue/focus validity, and response length. It retains no prompt, reply, key, endpoint or raw error. A plain safe-text fallback may validate dialogue but fails the full directed-focus schema gate. A passing local handler receipt still requires separate evidence of eligible Meta model identity and a deployed user experience; Fireworks/Modal model names are operator configuration, not eligibility verification.

`node --test tests/meta-live-probe.test.mjs` exercises all four handlers with injected synthetic responses, missing configuration, no-live refusal, text-only fallback and auth/rate/network failures. These are mocks and make no external requests.

For the current exact payload boundary, one-call cost estimate, provider choice, entrant/approval blockers and safe preview steps, see [Live Meta check and preview plan](META_LIVE_PREVIEW_PLAN.md). It is preparation only; it does not authorize keys, spending, live requests or deployment.
